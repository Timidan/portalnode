## Use

```tsx
import { PunchClock } from './anatomy';

<PunchClock />
// Verification theme:
<PunchClock theme="light" />
```

`PunchClockProps` exposes only `theme` and `className`. Model parameters, state and numerical readouts live in `model.ts`. There is no chain-data prop or fabricated live value.

- Vite preview: `/src/anatomy/preview.html` (append `?theme=light` for light).
- Standalone pages: `punch-clock.html` and `punch-clock-light.html`, with the same React component, CSS and runtime bundled inline. Both were opened and captured in Chromium without a dev server.
- Dark desktop reference: `shots/full-1440-dark.png`; phone: `shots/full-390-dark.png`.

Rebuild both standalone themes and solve geometry/motion order from the repository root:

```sh
node web/src/anatomy/build.mjs --audit
cd web && npx tsc --noEmit -p .
```

The audit build takes several minutes because it measures true overlaps across the motion path. `order.json` is generated by the kit's solver; do not tune its values by eye. `.build/` is temporary and ignored. The kit is copied intact under `iso/`, with LICENSE, attribution and narrow TypeScript declarations for the two JavaScript geometry modules used here.

## Scope and limits

- This is an illustrative claim-cycle model. It does not fetch chain data, sign transactions, measure balances, perform payouts, write SQLite or send Telegram alerts. Coin count and timing are symbolic, with no payout proportions claimed.
- The missed-claim expiry is separate from the successful keeper cycle. The stash key stays outside.
- This is a mechanical explanatory figure, not a manufacturing drawing or a full gear-train simulation.
- Parent-page integration and deployment are untested because they are outside the owned directory. Browser verification used Chromium; Safari/Firefox and physical touch hardware were not checked.
- No shader, audio, exploded view, pause/replay buttons or speculative live-data API was added.
